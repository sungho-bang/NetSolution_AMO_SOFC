# SOFCMeas 소스·기능 점검

점검일: 2026-09-07

## 결론

기본적인 설비별 수집 → 판정 → 메모리 누적 → LOT 저장 흐름은 동작한다. 다만 작업정보 입력, SPEC 정밀도, 설정 검증, 저장 오류 복구 등에서 개선이 필요하다. 이 문서는 점검 결과이며 제품 소스의 수정·운영 배포는 하지 않았다.

Release/x64 빌드를 별도 경로에 생성했다. WinForms 메시지 루프에서 실제 제품 클래스와 이벤트를 실행하고, 127.0.0.1에 두 개의 가상 PLC를 만들어 실제 McpX TCP/Binary/3E 통신 코드를 시험했다. 정상 동작 검증 41항목 통과, 실패 0항목. 별도의 문제 재현 조건 12개가 확인됐으며, 중복 증상을 묶으면 10개 문제 유형이다. 여기에 소스로 확인한 2개 위험을 추가했다.

## 우선 수정할 사항

### 1. [P1 / 실행 재현] 모델명·작업자·LOT 번호를 입력할 수 없다

세 입력란이 최초 생성 때부터 ReadOnly=true다. 입력 잠금을 해제하는 `HandleCreateFileRequested`는 존재하지만, 이를 호출할 `RaiseCreateFileRequested`가 실제 버튼이나 입력 이벤트에 연결되어 있지 않다. LOT 저장을 완료한 뒤에도 `SetLotPrepared(false, 0)`가 편집을 잠근다.

따라서 운영자가 새 작업정보를 입력할 수 없고, 화면의 기존/기본 작업정보가 다음 LOT에 계속 사용된다. 첫 시작과 LOT 종료 후 편집 경로를 복원하고, 수집·저장 중에만 잠가야 한다.

### 2. [P1 / 실행 재현] SPEC를 두 자리로 반올림한 뒤 판정한다

설정값을 `ToString("0.00")`으로 텍스트박스에 넣고, 판정은 그 텍스트를 다시 읽는다. 설정 SPEC=0.405, 최고값=0.407을 입력한 시험에서 실제 판정 기준은 0.41이 되어 NG가 나왔다. 원래 설정대로라면 GOOD이다. 현재 0.40 설정에는 이 차이가 없지만 설정 화면은 더 세밀한 SPEC를 허용한다.

판정 기준은 표시 문자열과 분리한 숫자값으로 유지해야 한다. 시뮬레이션에도 같은 반올림 코드가 있다. GOOD 조건인 `최고값 >= SPEC` 자체는 정상이다.

### 3. [P1 / 실행 재현] 저장 성공·실패의 경계가 불완전해 재시도 시 중복 CSV가 생긴다

LOT CSV를 최종 파일로 만든 다음 검사 로그 인덱스를 기록한다. 인덱스 파일이 잠겨 있는 조건에서 SaveLot은 실패를 반환했지만 최종 CSV는 이미 존재했다. 잠금을 풀고 같은 LOT를 재시도하면 별도 이름으로 CSV가 한 개 더 생겼다. UI는 실패 때 메모리를 보존하므로 실제 운영에서도 동일한 재시도 경로를 탄다.

LOT의 영속적인 저장 식별자를 두고 재시도 시 중복을 방지해야 한다. CSV 저장 완료와 인덱스 갱신 실패를 구분하고, 인덱스만 복구할 수 있어야 한다.

### 4. [P1 / 실행 재현] 허용된 Y축 설정으로 시작 화면 초기화가 실패한다

Graph.YMax는 읽지 않고 SPEC를 Y축 최대값으로 사용한다. YAuto=false, YMax=2, SPEC=0.4에서 실제 최대값은 0.4였다. 여기에 YMin=1을 지정하면 설정 검증은 통과하지만 ConfigureGraph에서 음수 간격 예외가 발생한다. 이 함수는 프로그램 시작 때도 호출된다.

설정 화면의 범위와 실제 축 계산을 일치시켜야 한다. SPEC 기반 시작 범위를 유지하려면 충돌하는 YMax 설정을 정리하고, 최종 계산된 최대값이 최소값보다 큰지 검증해야 한다.

## 정상 확인된 기능

- 두 PLC가 독립적으로 요청값과 LOAD_RAW를 읽고, Int32 원시값을 제수로 환산해 각각의 그래프와 결과에 반영한다.
- WAIT_START의 END 값에서는 LOAD_RAW를 읽지 않는다. START에서 읽고 END 뒤에는 읽기를 중단한다.
- EVALUATING/SAVING에서는 START와 LOAD_RAW 수집이 차단되며, 다른 설비는 계속 수집한다.
- 실제 통신 → UI BeginInvoke → 최고값 판정 → LOT 리스트 누적까지 연결한 시험에서 설비1 GOOD, 설비2 NG를 독립적으로 확인했다.
- 다음 START에서 그래프가 초기화되고 새 검사 값만 들어온다.
- 저장을 의도적으로 지연한 동안에도 새 START를 무시하고 저장 대상 리스트가 변하지 않았다.
- 설비1 LOT 저장 완료 후 설비1 리스트만 비워지고 설비2 결과는 보존됐다. 완료 알림을 생략한 시험에서는 저장 직후 수집 재개가 확인됐다.
- 최대 리스트 수를 넘으면 자동 저장하지 않고 가장 오래된 결과를 하나 제거한 뒤 신규 결과를 추가한다.
- 최고값이 SPEC와 같으면 GOOD이다. 판정 시 최고점 마커가 생성된다.
- 초기 X축 60회 기준은 최대 66, 간격 6.6이다. Y축도 10칸이며 X축 초과 입력 시 자동 확장된다.
- CSV 요약은 항목/값 2줄, RAWDATA는 kgf 소수점 3자리, 최대 샘플 수 기준 헤더와 짧은 행 빈칸 보정으로 저장된다.
- 저장 CSV를 다시 읽었을 때 하중이 이중 환산되지 않았다. REVIEW 그래프와 선택 번호 갱신, 빠른 연속 파일 클릭의 콤보 갱신을 확인했다.
- 시뮬레이션 60개 샘플 완료 및 취소 시 미완료 결과를 누적하지 않는 동작을 확인했다.
- 화면 ClientSize 높이는 1040이다. OPERATOR의 설정 저장은 거부된다.
- 등록 MAC 중 하나가 일치하면 허용하고, 등록 목록이 비면 거부한다. 기간 계산은 정확히 40일에서 만료되고 큰 시간 역행을 감지한다.
- 로그 저장·용량 분할·설비/세션/순번 식별이 동작한다.
- 별도 테스트 폴더에서 오래된 로그만 삭제되고 같은 날짜의 Data CSV가 남았다. Data 자체를 삭제 대상으로 넘기면 거부된다.

## 실제 설비에서 추가로 확인할 조건

1. 저장 중 발생한 START 값이 저장 종료까지 유지되면, 현재 코드는 새로운 신호 전이 없이도 그 값을 받아 수집을 시작한다. 이를 ‘저장 후 현재 START부터 수집’으로 볼지, ‘저장 중 시작한 검사는 END까지 완전히 제외’로 볼지 PLC와 기준을 맞춰야 한다.
2. 현재 운영 설정의 읽기 주기는 1000ms다. 폴링 사이에 START→END가 모두 지나가면 검사를 놓칠 수 있고, 짧은 END를 놓치면 두 검사가 합쳐질 수 있다. 실물 PLC의 신호 유지 시간 및 필요 시 ACK/완료 핸드셰이크를 확인해야 한다. 가상 시험은 신호를 충분히 유지했다.
3. 통신 단절 후 START 값이 남아 있는 경우, 실제 검사 중간부터 새 사이클로 재시작해도 되는지 확인해야 한다. 모든 재접속 경계 조합은 이번 시험에 포함되지 않았다.
4. LOT END 전까지 데이터는 메모리에만 있다. 강제 종료·정전 때 미저장 LOT가 복구되는 구조는 아니다. 이는 요청한 HDD 저장 시점과 관계된 운영 정책이므로 임의로 자동 저장을 추가하지 않았다.
5. START/STOP 버튼은 ‘다음 동작’이 아니라 현재 상태처럼 표시된다(수집 활성 시 START, 비활성 시 STOP). 운영자가 누를 동작으로 해석할 여지가 있어 상태 표시와 버튼 명칭을 분리하는 편이 명확하다.
