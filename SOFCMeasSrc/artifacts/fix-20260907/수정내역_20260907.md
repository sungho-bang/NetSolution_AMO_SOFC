# SOFCMeas 기능 수정 결과

2026-09-07 · Release / x64

## 적용 내용

- 모델명·작업자·LOT 번호 입력란을 항상 편집 가능하게 변경했다. 수집·저장 중에도 입력란 자체를 잠그지 않는다. SPEC는 설정에서 관리한다.
- 작업정보의 저장 기준은 LOT END를 누른 시점의 입력값으로 잡았다. 그 시점에 저장용 복사본을 만들어 CSV 요약과 검사 인덱스에 같은 내용을 사용한다. 저장 도중 변경한 입력은 진행 중인 파일을 바꾸지 않고 다음 LOT에 남는다.
- SPEC를 화면 문자열이 아닌 숫자값으로 보관하고 판정한다. 설정값 0.405가 0.41로 반올림되지 않는다. GOOD 조건은 최고값 >= SPEC 그대로다.
- Y축 최대값은 Graph.YMax 설정을 사용한다. YMin=1, YMax=2 같은 유효 설정도 정상 초기화된다. X축 10% 여유·자동 확장, Y축 10칸은 유지한다.
- REVIEW가 표시된 상태에서 검사 번호를 바꾸면 그래프와 판정을 함께 갱신한다. 파일만 읽는 동안 현재 검사 판정을 먼저 바꾸지 않는다.
- 검사수·GOOD·NG·Yield를 실제 롤링 LIST에 남은 검사 기준으로 다시 계산한다. CSV 요약과 집계 범위가 일치한다.
- START/END 요청값이 같으면 설정 저장을 거부하고, 기존 설정 파일을 읽을 때도 검증한다.
- 정수형 설정은 동일한 규칙으로 검증·로드하고 저장 시 정수 표기로 정규화한다. 12345.0, 1e3처럼 정수를 나타내는 값이 다른 기본값으로 바뀌지 않는다.
- PLC 자동 연결 OFF는 프로그램 시작 시 자동 연결만 막는다. 사용자의 START는 수동 연결 요청으로 처리한다.
- 상단에 로그 저장 상태를 추가했다. 저장 장애 시 오류를 표시하고 클릭하면 상세 원인을 볼 수 있다. 복구 후에도 누락 이력을 확인할 수 있다. 장애 동안 이미 누락된 로그를 복원하는 기능은 아니다.

## CSV와 인덱스 오류 복구

CSV 저장 완료 후 검사 로그 인덱스만 실패한 경우 CSV 저장을 실패로 되돌리지 않는다. 완료 메시지에 인덱스 복구 대기를 표시하고 메모리 LOT를 정상 정리한다.

CSV가 최종 파일이 되기 전에 `.csv.index.pending` 복구 정보를 남긴다. 인덱스는 임시 파일과 원자적 교체로 갱신하며 설비/데이터 파일/행 번호로 중복을 방지한다. 저장 직후, 프로그램 시작 시, 이후 30초 간격으로 복구를 시도한다. 성공한 복구 정보 파일만 제거하며 검사 CSV는 자동 삭제하지 않는다.

파일 저장 자체가 실패하면 기존처럼 메모리 검사는 유지한다. 한 저장 객체를 재시도해도 이미 완료된 CSV를 추가 생성하지 않는다.

## 요청대로 유지한 동작

- 저장 완료 메시지를 사용자가 확인하기 전까지 Reader는 SAVING 상태를 유지한다.
- 해당 시간에 PLC START가 들어와도 수집하지 않는다. 확인 후에만 요청값을 다시 처리한다.
- 설비별 독립 수집·판정, 해당 설비만 LOT 초기화, 데이터가 아닌 로그만 자동 삭제, RAWDATA kgf 소수점 3자리 저장을 유지한다.
- MAC 등록 및 40일 라이선스 정책은 변경하지 않았다.

## 검증과 배포

- 격리 환경 및 최종 배포 실행 파일에서 각각 회귀 테스트 65개 통과, 실패 0개.
- 가상 TCP/Binary/3E PLC 2개로 실제 통신 → UI 이벤트 → 그래프 → 판정 → LOT 저장 흐름 확인.
- SPEC 경계값, 축 초기화, REVIEW 동시 갱신, 롤링 집계, 잠긴 인덱스의 재시도·새 서비스에서 복구, 저장 중 작업정보 편집, 로그 장애·복구 표시, 수동 PLC 연결 확인.
- 자동 시험은 저장 완료 메시지 표시를 생략하고 수행했다. 메시지 확인 전 SAVING 유지 조건은 해당 분기의 소스 순서를 점검했으며 모달 창의 수동 클릭 시험은 수행하지 않았다.
- 실제 PLC 장비 연결 및 장시간 현장 운전 시험은 수행하지 않았다.
- 배포 위치: `C:\SOFCMeas\bin\SOFCMeas.exe`. 운영 설정 파일의 변경 전/후 SHA-256이 동일함을 확인했다. 운영 검사 데이터는 수정·삭제하지 않았다.
- 빌드 경고는 기존 Designer의 미사용 필드 5개이며 빌드 오류는 없다.
